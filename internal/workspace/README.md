# internal/workspace

- Role: sub-commands of `devzone workspace` ported to Go (#712, #754, #781). Ten so far:
  - `status`: prints the workspace pod (`kubectl get pods`), then the legacy copies still present in the pod, as the command always did.
  - `vscode` (`VSCode`, `vscode.go`): writes the fixed guide that attaches VS Code to the pod (namespace, pod and projects folder from the constants of `status.go`). No call to kubectl.
  - `shell` (`Shell`, `shell.go`): runs `kubectl [--context devzone] exec -it devzone-workspace-0 --namespace devzone-workspace -c workspace -- bash`, like `shell_workspace`. The caller passes its standard input (the terminal) as `stdin`: `ExecRunner` hands it to kubectl unchanged, so the terminal is inherited, and the status of kubectl is returned (a session interrupted with Ctrl-C keeps its 130). A kubectl that cannot start gives 127.
  - `stop` (`Stop`, `stop.go`): like `stop_workspace` in `manage/workspace.sh`. The port watcher of the workstation is stopped first (`stop_ports.go`, the port of `ports_stop` in `manage/scripts/workspace/ports-workspace.sh`: SIGTERM to the watcher and to each relay, then removal of the lock, the pid and the relay files of `.devzone.workspace-ports/`, or of `DEVZONE_PORTS_WORKSPACE_DIR`). Then `helm uninstall devzone-workspace --namespace devzone-workspace`.
  - `copy-to <folder>` (`CopyTo`, `copy.go`): as the command always did. The folder must exist and be a directory (`✖ folder not found: <folder>`, status 1). It is made absolute (`cd folder && pwd`), then the guard runs: `kubectl exec -i` sends `copyGuardScript` to the pod, which exits 3 when `/workspaces/projets/<name>` is a git clone of another remote. The copy is then refused with two lines on stderr (status 1). The remote of the workstation folder comes from `Origin` (`git -C folder remote get-url origin`), passed as an `OriginFunc` so that tests need no git. A pod that does not answer lets the copy go on. Then `kubectl cp <folder> devzone-workspace-0:/workspaces/projets/<name>`, with the status of kubectl.
  - `copy-from <folder>` (`CopyFrom`, `copy.go`): as the command always did. `kubectl cp devzone-workspace-0:/workspaces/projets/<name> <folder>`. The folder is made absolute only when it exists (`copy-from .` takes the current folder name); a folder not yet created keeps its path as given.
  - `clone <url> [<name>]` (`Clone`, `clone.go`): as the command always did. Without url, or with a folder name that is not valid (`.`, `..`, a leading `-`, or a character other than letters, digits, `.`, `_`, `-`; an empty name is shown as `empty`), it prints the message and returns 1 without any kubectl call. The name is taken from the url when none is given (`cloneName`: the last segment, without a trailing `/` or `.git`, and after the last `:`). The git `user.name` and `user.email` of the workstation are read with `Identity` (`git config --get`), passed as an `IdentityFunc` so that tests need no git; an unset value is an empty argument. Then `kubectl exec -i` runs `cloneScript` in the pod with `bash -s -- /workspaces/projets/<name> <url> <name> <email>`: `gh auth setup-git`, clone when the folder is missing, otherwise a check of its remote (exit 3 when it is another project), identity, then `repowarden install` in the clone. The status of the pod script is returned; a kubectl that cannot start gives 127.
  - `ports status` (`PortsStatus`, `ports_status.go`): like `ports_status` in `manage/scripts/workspace/ports-workspace.sh` and `pa_status` in `manage/scripts/workspace/ports-apps.sh`. Reads the state folder of `portsDir()`, then writes, in this order: the watcher line (running when its pid is alive, stopped otherwise), the relays whose pid is alive (`  127.0.0.1:<name> relayed`), every file of `taken/` (warning), the applications of `apps/` whose local relay is alive, and those of `no-ready-pod/` whose application exists. Entries are read in the lexicographic order of their names, hidden ones ignored; a missing state folder gives only the stopped watcher. Status always 0.
  - `ports stop` (`PortsStop`, `ports_status.go`): calls `stopPorts` (the port of `ports_stop`) and returns 0, printing nothing.
  - `services status` (`ServicesStatus`, `services_status.go`): like `services_status` in `manage/scripts/workspace/services-workspace.sh`. One line per service of the cluster in the order gitlab, postgres, mysql, argocd: `  ✔ s installed (namespace ns): devzone workspace services disable s` when the call `kubectl [--context devzone] get namespace ns` succeeds, `  ○ s not installed: devzone workspace services enable s` otherwise (also when kubectl cannot start: all the lines are then "not installed"). Status 0.
  - Argo CD state building blocks (#781, lot A1.4b), not wired yet: `argocdWanted` (`argocd_state.go`) is true unless `.devzone.modules` holds exactly `argocd=off` (an absent key, `false` and `Off` stay wanted); `argocdInstalled` runs `kubectl [--context devzone] get namespace devzone-argocd` and ignores its output and errors; `argocdActive` is wanted and installed, and calls no kubectl when off; `argocdQuantityKi` converts a memory quantity in the shell order (Ki, Mi, Gi, Ti, K or k, M, G, then bare bytes, with integer divisions) and gives 0 to an empty value, an unknown suffix or a decimal; `argocdRevision` returns `DEVZONE_ARGOCD_REVISION` when non-empty, otherwise `v` plus the first `"version"` line of `package.json` (the last occurrence on that line), or an empty string for an empty version, `0.0.0` and a missing file. `argocd_state_test.go` covers them with the fake `Runner`; `argocd_state_bash_test.go` compares the status, the kubectl calls and the outputs with the shell original, with a fake `kubectl` in the PATH, and is skipped without bash and on Windows.
  - Argo CD memory check (#781, lot A1.4c), not wired yet: `argocdMemoryOK` (`argocd_memory.go`) sums the allocatable memory of the nodes, in Ki with `argocdQuantityKi`, and refuses the installation with status 2 under 1 Gi, writing the reason on the error output; a cluster that does not answer gives the unreachable message. The shell message ends with `enlarge the cluster (<product> -> Settings -> Resources), then:` while the Go writes `enlarge the memory of the cluster, then:`, the product name being retired by another ticket. `argocd_memory_test.go` and `argocd_memory_bash_test.go` cover them with the fake `Runner` and the fake `kubectl` in the PATH.
  - Modules state building blocks (#781, lot A1.4a), used by `argocd`, `services`, `egress`, `start` and `update`. `readModulesKey` (`modules_state.go`) returns the value of the last `key=` line of `.devzone.modules`, after the first `=`, with carriage returns and spaces kept; a missing file or key gives an empty value. `noteModulesKey` removes every `key=` line, keeps the other lines in order (blank lines and carriage returns included), appends `key=value`, and writes through a neighbor temporary file and a rename with mode 0644. Both mirror `state_read` and `state_note` of `argocd-workspace.sh`; the shell treats the key as a regular expression while Go treats it as plain text. Nothing calls them yet. `modules_state_test.go` covers both functions in a temporary folder, and `modules_state_bash_test.go` compares their bytes with the shell original; the comparison is skipped without bash and on Windows.
  - Port watcher building blocks (#781, lot A1.2a), called by the round and the loop below. `ports_apps.go`: `serviceExcluded` (`pa_excluded`: skipped namespaces, `default/kubernetes`, annotation `devzone.io/relay: false`, `ExternalName`, no address or `None`), `parseDiscovered` and `discoverServices` (`pa_discover`: lines `namespace|name|clusterIP|type|annotation|port/proto,`, only numeric `*/TCP` ports), `parseReady` and `readyServices` (`pa_ready`: set of `namespace/name` with a ready endpoint; a failing call returns `errEndpointsUnreadable`, which the shell turns into "relay everything", so the caller decides), `localPortFree` and `newLocalPort` (`pa_free`, `pa_new`: the Service port itself when 1024 and above and free, otherwise port + 8000 then upwards, back to 20000 after 65000, 60000 tries, then `errNoFreePort`). `ports_services.go`: `watcherContext` and `watcherKubectl` (`pw_ctx`, `pw_kubectl`), `watchedServices` (`pw_services`: postgres, pgAdmin, mysql and Argo CD from `.devzone.modules`, `DEVZONE_ARGOCD_PORT`), `podPorts` (`pw_pod_ports`: `ss -ltnH` in the pod, 1024 and above, without 2475 and 1234) and `portTaken` (`pw_taken`: listening on 127.0.0.1 fails; lsof or nc in the shell, so a port below 1024 counts as taken here and a listener on another address may go unseen). Known differences: a failing `ss` call gives no port (the shell keeps what kubectl printed), and a `DEVZONE_ARGOCD_PORT` that is not a number gives 8443 (the shell would print it as it is).
  - `ports_bash_test.go` and `ports_bash_services_test.go` run the bash functions (`pa_excluded`, `pa_new`, `pw_services`, `pw_pod_ports`, `pa_ready`, `pa_discover`) from `manage/scripts/workspace/ports-workspace.sh` with a fake `kubectl` in the PATH and compare outputs and every kubectl call with the Go functions; they are skipped without bash and on Windows.
  - Port watcher round (#781, lot A1.2b-1), run by the watcher loop below. `ports_round.go`: `PortsRound(out, errOut)` is one round of `pw_round`, with `pw_relay` and `pw_remove` (state folder `portsDir()`, status always 0). The wanted ports are the services of the modules, then the ports listening in the pod (relayed to `pod/devzone-workspace-0`), then the applications; for each, a live process in `relays/<port>` means nothing to do, a port taken on the workstation creates `taken/<port>` and prints the warning once, otherwise `kubectl [--context devzone] --namespace <ns> port-forward --address 127.0.0.1 <target> <local>:<remote>` is started detached, its pid written in `relays/<port>`, and `→ port N relayed on 127.0.0.1` printed; then the relays and markers of ports no longer wanted are removed (`removeRelay`). `ports_round_apps.go`: `appRound.run` is `pa_round` (state in `apps/`, `cap/`, `no-ready-pod/` and the marker `endpoints-unreadable`; local ports kept from one round to the next; at most 30 relays, `appsMax`; one `get svc` and one `get endpointslices` per round; warnings on the error output, once each). `process_start_unix.go` and `process_start_windows.go`: `startDetached` starts the relay with no input or output, in its own session, and a goroutine waits for it so that a dead relay stops being alive (the shell collects its dead children, Go does not, and `kill -0` is true for a zombie); on Windows it returns an error. Known differences: a stored local port written with leading zeros is rewritten without them; a relay that cannot start prints `⚠ port N not relayed: <error>` on the error output (the shell cannot fail there); the relay session is new (`Setsid`) where the shell keeps its own.
  - Tests of the round: `ports_round_apps_test.go` (fake `Runner`, no process), `ports_round_test.go` and `process_start_unix_test.go` (a fake `kubectl` in the PATH that sleeps on `port-forward`; every process is killed when the test ends), and `ports_round_bash_test.go` with `ports_round_scenarios_test.go`, which run `ports-workspace.sh round` and the Go round on two state folders and compare the printed lines (both streams), the state files, the number of live relays and the `kubectl` calls; skipped without bash, lsof or nc, and on Windows.
  - `ports start` and the watcher loop (#781, lot A1.2b-2), the first part of `ports` where the user sees the Go code: the watcher is now launched by Go. `ports_start.go`: `PortsStart(out, errOut)` is `ports_start`: under bats without `DEVZONE_PORTS_WORKSPACE_REAL=yes` it prints `✖ port watcher refused under bats (DEVZONE_PORTS_WORKSPACE_REAL=yes required)` on the error output and does nothing else (status 0); otherwise it creates the state folder, removes the `restart` signal, prints `Workspace ports: watcher already running (pid N)` when `pid` names a live process, else removes the `lock` folder and takes it again with an atomic `mkdir` (failure: silent, status 0), starts `<this binary> workspace ports loop` detached (`startDetached`: no input, output and errors appended to `journal.log`, new session), writes its pid in `pid` and prints `Workspace ports: watcher started, log <folder>/journal.log`. The binary is `os.Executable()`, replaceable through `watcherExecutable` for tests. `ports_loop.go`: `PortsLoop(step)` is `pw_loop`: it ignores SIGHUP (the `nohup` of the shell), runs `PortsRound` and waits `step` (`PortsStep()`: `DEVZONE_PORTS_WORKSPACE_STEP` seconds, 3 when missing, invalid or not positive; a fraction is accepted); on SIGTERM or SIGINT, also during the wait, it removes its relays, `lock` and `pid` and returns 0. `internal/command` runs `ports start` and the internal `ports loop` (not in the help) in Go; on Windows both stay out of Go and `ports start` is delegated to bash, whose watcher is a shell process. A watcher started by the shell is seen by `ports status` and stopped by `ports stop` of Go, and the other way round: same state folder, same messages. `.devcontainer/rename-legacy-ports.sh` (`is_watcher`) recognises a process whose command holds `workspace ports loop` as a watcher. Known differences: a watcher that cannot be launched prints `✖ port watcher not started: <error>` on the error output, releases the lock and returns 1 (the shell cannot fail there); a fractional or invalid step is accepted or replaced by 3 where the shell passes the text to `sleep`; `startDetached` keeps the streams the caller set on the command.
  - Tests of `ports start` and the loop (`ports_start_*_test.go`, not built on Windows): `ports_start_test.go` builds the real binary once (`TestMain` removes it) and runs it with a fake `kubectl` in the PATH (start, status, second start, stop, SIGTERM within a 30 s step, SIGHUP ignored, guard under bats); `ports_start_state_test.go` covers the `restart` signal, a stale lock, a lost lock, a launch failure; `ports_start_bash_test.go` compares the messages with `ports_start` of the bash script and checks that a bash watcher is seen and stopped by Go. Every watcher, relay and child is stopped at the end of each test, also on failure (`liveEnv.reap`).
  - Only the one-folder form of `copy-to` and `copy-from` is ported: `internal/command` delegates them alone, or with extra words, to bash. `clone` is ported with one or two words (url and name): alone, or with more words, it is delegated. `ports` is ported without a word (`status`) and with `start`, `status`, `stop` or the internal `loop`: on Windows `ports start` is delegated, and so are the renamed words and any extra word everywhere.
  - Message and status of both: no folder argument gives `✖ provide a workstation folder: devzone workspace copy-to <folder>` (or `copy-from`) and status 1.
- Scripts run in the pod: `podScript` (`legacy.go`) and `copyGuardScript` (`copy_guard.go`) are copies of the heredocs of `manage/scripts/workspace/workspace-copies.sh`; `cloneScript` (`clone_script.go`) is a copy of the heredoc of `manage/scripts/workspace/workspace-clone.sh`. `pod_script_test.go` reads those files and fails when a copy differs from its bash original, so both stay identical until the bash copy is removed.
- Argo CD fallback: when the namespace `devzone-argocd` exists and holds the Application `devzone-workspace`, `Stop` calls the `fallback` it receives and returns its status. Argo CD removal goes through the GitOps repository (GitHub or GitLab, git, gh), which stays in bash. The check is read-only and runs before any change, so the bash run starts from the same state.
- Calling `kubectl` and `helm`: through the `Runner` interface (`Kubectl` and `Helm`, each with `args, stdin, stdout, stderr`). `ExecRunner` runs the programs found in the PATH; the tests replace `Runner` with a fake, without a cluster. A non-nil `stdin` is piped to the program; an `*os.File` (the terminal) is passed as the file descriptor itself, so `kubectl exec -it` gets the terminal. This is why the interface needed no change for `shell`.
- Context: `--context devzone` for kubectl and `--kube-context devzone` for helm, when the kubeconfig declares the `devzone` context, otherwise the current context (like `kubectl_flag` and `helm_flag`).
- Exit codes: `status` returns the one of `kubectl get pods` (a missing or failing pod is not an error: the pod status is printed); `stop` returns the one of `helm uninstall`, or of the bash fallback; `shell` returns the one of `kubectl exec -it`; `vscode` returns 0; `ports status` and `ports stop` return 0 in all cases. `status`, `stop` and `shell` give 127 when the program cannot start. The legacy copies check never fails `status`: when the pod does not answer, nothing is printed.
- Parity: `manage/test/go-parity.bats` compares the output and the status with the bash script, with a fake `kubectl` and a fake `helm` in the PATH.
- May import: the standard library only.
- Must not import: `internal/command`, `internal/bashbridge` or `cmd/...`.
- Tests: `go test ./internal/workspace/`. `copy_test.go` runs the copies with the fake `Runner` (no cluster), `clone_test.go` runs the clone the same way and checks `Identity` with a git config file of the test, `git_helpers_test.go` checks `Origin` on real git repositories, and `ports_status_test.go` builds a temporary state folder with real `sleep` processes (no network). The remaining sub-commands (`start`, the renamed words of `ports`, ...) stay in `manage/workspace.sh` and are delegated to bash by `internal/command`.
