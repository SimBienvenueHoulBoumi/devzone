# internal/workspace

- Role: sub-commands of `devzone workspace` ported to Go (#712, #754). Seven so far:
  - `status`: prints the workspace pod (`kubectl get pods`), then the legacy copies still present in the pod, like `status_workspace` in `manage/scripts/workspace/workspace-copies.sh`.
  - `vscode` (`VSCode`, `vscode.go`): writes the fixed guide that attaches VS Code to the pod, byte for byte as `vscode_workspace` in `manage/workspace.sh` (namespace, pod and projects folder from the constants of `status.go`). No call to kubectl.
  - `shell` (`Shell`, `shell.go`): runs `kubectl [--context devzone] exec -it devzone-workspace-0 --namespace devzone-workspace -c workspace -- bash`, like `shell_workspace`. The caller passes its standard input (the terminal) as `stdin`: `ExecRunner` hands it to kubectl unchanged, so the terminal is inherited, and the status of kubectl is returned (a session interrupted with Ctrl-C keeps its 130). A kubectl that cannot start gives 127.
  - `stop` (`Stop`, `stop.go`): like `stop_workspace` in `manage/workspace.sh`. The port watcher of the workstation is stopped first (`stop_ports.go`, the port of `ports_stop` in `manage/scripts/workspace/ports-workspace.sh`: SIGTERM to the watcher and to each relay, then removal of the lock, the pid and the relay files of `.devzone.workspace-ports/`, or of `DEVZONE_PORTS_WORKSPACE_DIR`). Then `helm uninstall devzone-workspace --namespace devzone-workspace`.
  - `copy-to <folder>` (`CopyTo`, `copy.go` and `copy_guard.go`): like `copy_to` in `manage/workspace.sh`. The folder must exist and be a directory (`✖ folder not found: <folder>`, status 1). It is made absolute (`cd folder && pwd`), then the guard runs: `kubectl exec -i` sends `copyGuardScript` to the pod, which exits 3 when `/workspaces/projets/<name>` is a git clone of another remote. The copy is then refused with two lines on stderr (status 1). The remote of the workstation folder comes from `Origin` (`git -C folder remote get-url origin`), passed as an `OriginFunc` so that tests need no git. A pod that does not answer lets the copy go on. Then `kubectl cp <folder> devzone-workspace-0:/workspaces/projets/<name>`, with the status of kubectl.
  - `copy-from <folder>` (`CopyFrom`, `copy.go`): like `copy_from`. `kubectl cp devzone-workspace-0:/workspaces/projets/<name> <folder>`. The folder is made absolute only when it exists (`copy-from .` takes the current folder name); a folder not yet created keeps its path as given.
  - `clone <url> [<name>]` (`Clone`, `clone.go`): like `workspace_clone` in `manage/scripts/workspace/workspace-clone.sh`. Without url, or with a folder name that is not valid (`.`, `..`, a leading `-`, or a character other than letters, digits, `.`, `_`, `-`; an empty name is shown as `empty`), it prints the message and returns 1 without any kubectl call. The name is taken from the url when none is given (`cloneName`: the last segment, without a trailing `/` or `.git`, and after the last `:`). The git `user.name` and `user.email` of the workstation are read with `Identity` (`git config --get`), passed as an `IdentityFunc` so that tests need no git; an unset value is an empty argument. Then `kubectl exec -i` runs `cloneScript` in the pod with `bash -s -- /workspaces/projets/<name> <url> <name> <email>`: `gh auth setup-git`, clone when the folder is missing, otherwise a check of its remote (exit 3 when it is another project), identity, then `repowarden install` in the clone. The status of the pod script is returned; a kubectl that cannot start gives 127.
  - Only the one-folder form of `copy-to` and `copy-from` is ported: `internal/command` delegates them alone, or with extra words, to bash. `clone` is ported with one or two words (url and name): alone, or with more words, it is delegated.
  - Message and status of both: no folder argument gives `✖ provide a workstation folder: devzone workspace copy-to <folder>` (or `copy-from`) and status 1.
- Scripts run in the pod: `podScript` (`legacy.go`) and `copyGuardScript` (`copy_guard.go`) are copies of the heredocs of `manage/scripts/workspace/workspace-copies.sh`; `cloneScript` (`clone_script.go`) is a copy of the heredoc of `manage/scripts/workspace/workspace-clone.sh`. `pod_script_test.go` reads those files and fails when a copy differs from its bash original, so both stay identical until the bash copy is removed.
- Argo CD fallback: when the namespace `devzone-argocd` exists and holds the Application `devzone-workspace`, `Stop` calls the `fallback` it receives and returns its status. Argo CD removal goes through the GitOps repository (GitHub or GitLab, git, gh), which stays in bash. The check is read-only and runs before any change, so the bash run starts from the same state.
- Calling `kubectl` and `helm`: through the `Runner` interface (`Kubectl` and `Helm`, each with `args, stdin, stdout, stderr`). `ExecRunner` runs the programs found in the PATH; the tests replace `Runner` with a fake, without a cluster. A non-nil `stdin` is piped to the program; an `*os.File` (the terminal) is passed as the file descriptor itself, so `kubectl exec -it` gets the terminal. This is why the interface needed no change for `shell`.
- Context: `--context devzone` for kubectl and `--kube-context devzone` for helm, when the kubeconfig declares the `devzone` context, otherwise the current context (like `kubectl_flag` and `helm_flag`).
- Exit codes: `status` returns the one of `kubectl get pods` (a missing or failing pod is not an error: the pod status is printed); `stop` returns the one of `helm uninstall`, or of the bash fallback; `shell` returns the one of `kubectl exec -it`; `vscode` returns 0. `status`, `stop` and `shell` give 127 when the program cannot start. The legacy copies check never fails `status`: when the pod does not answer, nothing is printed.
- Parity: `manage/test/go-parity.bats` compares the output and the status with the bash script, with a fake `kubectl` and a fake `helm` in the PATH.
- May import: the standard library only.
- Must not import: `internal/command`, `internal/bashbridge` or `cmd/...`.
- Tests: `go test ./internal/workspace/`. `copy_test.go` runs the copies with the fake `Runner` (no cluster), `clone_test.go` runs the clone the same way and checks `Identity` with a git config file of the test, and `git_helpers_test.go` checks `Origin` on real git repositories. The remaining sub-commands (`start`, `ports`, ...) stay in `manage/workspace.sh` and are delegated to bash by `internal/command`.
