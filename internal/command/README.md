# internal/command

- Role: receives the devzone command line; runs in Go the commands of the `ported` table, delegates the others to the bash bridge (#358).
- May import: the standard library, `internal/bashbridge` and `internal/workspace`.
- Must not import: `cmd/...` (the binary depends on this package, never the reverse) nor a business package that would depend on bash.
- The `ported` table lists the ported commands: `--version`, `-v`, `help`, `-h`, `--help`, only alone, with no other argument; and `workspace`, for the `status`, `stop`, `vscode` and `shell` sub-commands only (#712), for `copy-to` and `copy-from` with one folder argument (#754), and for `clone` with a url and an optional name (#754): `workspaceCommand` in `workspace.go`. A command enters it when it is ported, and leaves the delegation in the same change. `devzone workspace` followed by anything else (another sub-command, or one of these followed by a word) stays delegated to bash. `workspace stop` is delegated too when Argo CD holds the workspace (see `internal/workspace/README.md`). `workspace shell` receives the terminal of the user as standard input. `ports start`, `ports loop` and `ports agent` run in Go on Windows too (#883): the watcher has real process primitives there; only its automatic start stays out of Go, as it belongs to another ticket. `workspace services enable|disable|seed` run in Go for the forms that do not need Argo CD, `start` runs in Go when Argo CD is off and absent, and `argocd` and `argocd status` run in Go with the shared `.argocd.conf` reader; the other forms stay delegated to bash until the GitOps libraries are ported.
- Tests: `go test ./internal/command/`; the delegation tests use a fake bash entry point, those of `workspace status`, `stop`, `vscode`, `shell`, `copy-from` and `clone` a fake `kubectl` (and a fake `helm`) in the PATH.
